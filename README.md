
Limitations & boilerplates/Limitações e esquemas repetitivos:

en-us*

- AddrsR is currently in a "prototype" state, so there are quite a few limitations and specifications you need to pay attention to while using it.
- The framework still has some boilerplate code, like using "path functions" in the dependency/needs system.
- Dependencies are strictly resolved during the lifecycle phase, meaning you can't dynamically inject modules after the boot step.

pt-br*

O AddrsR atualmente tá em estado de "protótipo", então tem uma série de limitações e especificações que você precisa prestar atenção na hora de usar.
O framework ainda tem um bocado de código repetitivo (boilerplate), tipo as "path functions" no sistema de dependências/needs.
As dependências são resolvidas estritamente durante a fase de ciclo de vida (lifecycle), o que significa que não dá pra injetar módulos dinamicamente depois do boot.
